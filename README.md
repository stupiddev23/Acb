<h2 id="requirements">Requirements</h2> <p>Before running the bot, make sure you have the following installed:</p> <ul> <li><b>Node.js</b> 18 or newer, for the built-in <code>fetch</code> used by web search</li> <li><b>npm</b></li> <li><b>Ollama</b></li> <li><b>An Ollama-compatible AI model</b></li> <li><b>A Minecraft server</b> that allows your bot to connect</li> </ul> <h3>Recommended Model</h3> <p> The bot works with any Ollama-compatible model. The current configuration uses: </p> <p> <code>qwen-heretic</code> </p> <p> You can replace this with any model installed in Ollama. </p>
<h2 id="installation">Installation</h2> <h3>1. Clone the Repository</h3> <p>Clone the repository and enter the project directory:</p> <pre><code>git clone https://github.com/ExploitedTux/AiChatBot.git cd AiChatBot</code></pre> <h3>2. Install Dependencies</h3> <p>Install all required Node.js dependencies:</p> <pre><code>npm install</code></pre> <h3>3. Install Ollama</h3> <p> Install <a href="https://ollama.com/">Ollama</a> on your system. Make sure Ollama is running before starting the bot. </p> <h3>4. Install an AI Model</h3> <p>The default configuration uses <code>qwen-heretic</code>.</p> <pre><code>ollama pull qwen-heretic</code></pre> <p>Check your installed models with:</p> <pre><code>ollama list</code></pre> <p> You can use any other compatible model as long as it is installed locally and configured in <code>config.json</code>. </p> <h3>5. Configure the Bot</h3> <p> Open <code>config.json</code> and configure the bot to match your Minecraft server and Ollama setup. </p> <h3>6. Start the Bot</h3> <pre><code>node ChatBot.js</code></pre> <p> The bot should now connect to your Minecraft server and be ready to use. </p>
<h2 id="configuration">Configuration</h2> <p> The bot uses <code>config.json</code> for its main configuration. </p> <h3>Example Configuration</h3> <pre><code>{ "username": "AiBot", "password": "CHANGE_ME", "Ip": "localhost", "blacklist": [ "ExamplePlayer" ], "msglist": [ "Chat with me using ?ai", "Ask me something with ?ai" ], "AI_MODEL": "qwen-heretic", "MAX_HISTORY": 8, "AI_COOLDOWN": 6000, "CHAT_COOLDOWN": 8000, "MC_CHAT_LIMIT": 150, "MAX_CONTINUATIONS": 2, "RECONNECT_DELAY": 5000, "AI_PREFIX": "?ai", "WEB_SEARCH": true, "SEARCH_MODE": "auto", "SEARCH_PROVIDER": "duckduckgo", "SEARCH_URL": "", "SEARCH_MAX_RESULTS": 4, "SEARCH_MAX_CHARS": 900, "SEARCH_TIMEOUT": 8000, "AI_NUM_PREDICT": 55, "SEARCH_NUM_PREDICT": 110 }</code></pre> <h3>Minecraft Connection</h3> <table> <tr> <th>Setting</th> <th>Description</th> </tr> <tr> <td><code>username</code></td> <td>Minecraft username used by the bot.</td> </tr> <tr> <td><code>password</code></td> <td>Optional password used for servers requiring <code>/login</code>.</td> </tr> <tr> <td><code>Ip</code></td> <td>Minecraft server address.</td> </tr> </table> <h3>Player Blacklist</h3> <p> Players listed under <code>blacklist</code> will be ignored by the AI. </p> <pre><code>"blacklist": [ "PlayerOne", "PlayerTwo" ]</code></pre> <h3>Startup Messages</h3> <p> The <code>msglist</code> setting contains messages the bot can randomly send after joining the server. </p> <pre><code>"msglist": [ "Chat with me using ?ai", "Ask me something with ?ai", "What's up?" ]</code></pre> <h3>AI Model</h3> <pre><code>"AI_MODEL": "qwen-heretic"</code></pre> <p> Replace <code>qwen-heretic</code> with any compatible Ollama model installed on your system. </p> <h3>Cooldowns</h3> <pre><code>"AI_COOLDOWN": 6000, "CHAT_COOLDOWN": 8000</code></pre> <table> <tr> <th>Setting</th> <th>Description</th> </tr> <tr> <td><code>AI_COOLDOWN</code></td> <td>Controls how often an individual player can request an AI response.</td> </tr> <tr> <td><code>CHAT_COOLDOWN</code></td> <td>Controls the delay between messages sent by the bot.</td> </tr> </table> <p> <b>All cooldown values are in milliseconds.</b> </p> <h3>Conversation History</h3> <pre><code>"MAX_HISTORY": 8</code></pre> <p> Controls how much conversation history is kept for each player. Higher values provide more context but can use more tokens and memory. </p> <h3>Response Length</h3> <pre><code>"MC_CHAT_LIMIT": 150, "MAX_CONTINUATIONS": 2</code></pre> <table> <tr> <th>Setting</th> <th>Description</th> </tr> <tr> <td><code>MC_CHAT_LIMIT</code></td> <td>Maximum size of each Minecraft chat message.</td> </tr> <tr> <td><code>MAX_CONTINUATIONS</code></td> <td>Maximum number of times the bot can continue an AI response.</td> </tr> </table> <h3>AI Prefix</h3> <pre><code>"AI_PREFIX": "?ai"</code></pre> <p> Players use the configured prefix to talk to the bot. </p> <pre><code>?ai hello</code></pre>
<h2 id="web-search">Web Search</h2> <p> The bot can look information up on the internet before it answers. When a prompt asks about something current (&quot;latest&quot;, &quot;news&quot;, &quot;price&quot;, &quot;who won&quot;, a year, ...) or explicitly asks the bot to search, it fetches a few result snippets, gives them to the model, and then replies. The conversation history still only stores the player prompt and the answer, so results do not pile up in memory. </p> <pre><code>"WEB_SEARCH": true,
"SEARCH_MODE": "auto",
"SEARCH_PROVIDER": "duckduckgo"</code></pre> <table> <tr> <th>Setting</th> <th>Description</th> </tr> <tr> <td><code>WEB_SEARCH</code></td> <td>Set to <code>false</code> to turn internet lookups off completely.</td> </tr> <tr> <td><code>SEARCH_MODE</code></td> <td><code>auto</code> searches only when the prompt looks like it needs current information, <code>always</code> searches on every prompt, <code>off</code> never searches.</td> </tr> <tr> <td><code>SEARCH_PROVIDER</code></td> <td>One of <code>duckduckgo</code> (default), <code>bing</code>, <code>wikipedia</code> or <code>searxng</code>. None of them need an API key.</td> </tr> <tr> <td><code>SEARCH_URL</code></td> <td>Base URL of your own SearXNG instance for the <code>searxng</code> provider, for example <code>http://127.0.0.1:8080</code>. Only needed if you want to run your own search engine instead of the public ones.</td> </tr> <tr> <td><code>SEARCH_MAX_RESULTS</code></td> <td>How many results are given to the model. Default <code>4</code>.</td> </tr> <tr> <td><code>SEARCH_MAX_CHARS</code></td> <td>Character limit of the search context handed to the model. Default <code>900</code>.</td> </tr> <tr> <td><code>SEARCH_TIMEOUT</code></td> <td>Total time budget for one lookup in milliseconds, shared by the provider and its fallbacks. Default <code>8000</code>.</td> </tr> <tr> <td><code>SEARCH_NUM_PREDICT</code></td> <td>Max tokens of a reply that used search results. Default <code>110</code>, because a sourced answer needs more room than small talk.</td> </tr> <tr> <td><code>AI_NUM_PREDICT</code></td> <td>Max tokens of a normal reply. Default <code>55</code>.</td> </tr> </table> <p> If the chosen provider fails, the bot falls back to Bing, DuckDuckGo and Wikipedia, and if everything fails it answers from the model's own knowledge instead of erroring out in chat. Searches are logged to the console as <code>[SEARCH] &quot;query&quot; -&gt; 4 results via duckduckgo</code>. <br><br> The keyless providers are free and need no sign up, but a search engine may rate limit or block a host. If DuckDuckGo returns an empty page, the bot retries the same query through the Jina reader proxy, then Bing, then Wikipedia. No account, API key or payment is needed for any of the providers. For a setup that never depends on a public host at all, point <code>SEARCH_URL</code> at your own <a href="https://docs.searxng.org/">SearXNG</a> instance. </p>
<h2 id="free-ai">Free AI Fallback</h2> <p> When the local Ollama model cannot answer, the bot can ask a free hosted model instead. This happens in two cases: Ollama errors out, or its reply is a &quot;I don't know / I'm not sure / I couldn't find it&quot; style answer. The fallback uses <a href="https://pollinations.ai/">Pollinations</a>' public text API, which needs no account, API key, card or sign up. The answer replaces the &quot;I don't know&quot; in that player's history, so the bot does not repeat the same dead end. </p> <pre><code>"FREE_AI_FALLBACK": true,
"FREE_AI_URL": "https://text.pollinations.ai/openai",
"FREE_AI_MODEL": "openai"</code></pre> <table> <tr> <th>Setting</th> <th>Description</th> </tr> <tr> <td><code>FREE_AI_FALLBACK</code></td> <td>Set to <code>false</code> to keep every answer on your own Ollama model.</td> </tr> <tr> <td><code>FREE_AI_URL</code></td> <td>OpenAI-compatible chat endpoint. Defaults to the keyless Pollinations endpoint.</td> </tr> <tr> <td><code>FREE_AI_MODEL</code></td> <td>Model name sent to that endpoint. Default <code>openai</code>, which Pollinations serves as GPT-OSS 20B.</td> </tr> <tr> <td><code>FREE_AI_TIMEOUT</code></td> <td>How long to wait for the fallback in milliseconds. Default <code>20000</code>.</td> </tr> <tr> <td><code>FREE_AI_MAX_CHARS</code></td> <td>Maximum length of a fallback answer before it is trimmed. Default <code>400</code>.</td> </tr> <tr> <td><code>FREE_AI_COOLDOWN</code></td> <td>Minimum milliseconds between fallback requests. Default <code>45000</code>, matching the free tier limit.</td> </tr> </table> <p> The free tier allows <b>one reply every 45 seconds per IP</b>, so the fallback is best effort: the bot waits for the next free slot instead of hammering the service, and if the slot is not available yet it keeps the local answer or reports the error as usual. The limit is per IP, so a busy server with many players will mostly answer with your own Ollama model. </p> <p> Fallback answers are trimmed of markdown, capped in length and logged as <code>[FREE AI] ...</code>, and they get the same web search results as the local model when a search was made. </p> <p> <b>Privacy:</b> when the fallback fires, that player's question and any search snippets are sent to the public Pollinations service. Set <code>FREE_AI_FALLBACK</code> to <code>false</code> if every conversation must stay on your machine. </p>
<h2>Customizing the AI</h2> <p> The bot's personality is controlled by the system prompt inside <code>ChatBot.js</code>. </p> <p> You can change the prompt to create different personalities, speaking styles, or behaviors. </p> <h3>Example</h3> <pre><code>const MommyPrompt = `You are a friendly Minecraft player who enjoys talking with people on the server.`;</code></pre> <p> You can modify this prompt without changing the rest of the bot. </p>
<h2 id="usage">Usage</h2> <h3>Start the Bot</h3> <pre><code>node ChatBot.js</code></pre> <p> Once the bot joins the server, players can talk to it using the configured prefix. </p> <h3>Example</h3> <pre><code>?ai hello</code></pre> <p> The bot will respond directly in Minecraft chat. </p> <h3>Conversation Memory</h3> <p> Each player has their own conversation history. This means conversations between different players do not get mixed together. </p>
